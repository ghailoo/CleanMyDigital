# CleanMyDigital — Apple HIG audit, 2026-10-12

macOS SwiftUI app, version 1.2. Audited against the current Human Interface
Guidelines (fetched 2026-10-12: App icons, Typography, Accessibility, Color,
The menu bar) plus a static scan of the project.

The audit skill is written for iOS/watchOS. iOS-only rules (44×44 pt touch
targets, haptics, tab bars, Dynamic Type sizing) don't apply to a Mac app and
were excluded. Simulator runtime checks don't apply either — this is a Mac
app, so dark mode and large-text checks need a human looking at the app.

## Findings

### 1. App icon is a flattened PNG set, not a layered icon — medium

**HIG (App icons):** "Although you can provide a flattened image for your icon,
layers give you the most control over how your icon design is represented…
iOS, iPadOS, macOS, and watchOS app icons include a background layer and one or
more foreground layers… These icons take on Liquid Glass attributes like
specular highlights, refraction, and translucency."

**App:** `Assets.xcassets/AppIcon.appiconset` holds ten flat PNGs
(`icon_16x16.png` … `icon_512x512@2x.png`), generated from one 1024 px render.
There is no `.icon` document and no dark or mono variant.

**Effect:** the icon looks correct but static. It won't pick up the system's
icon effects, and it shows the same artwork in light mode, dark mode and
tinted contexts.

**Fix:** rebuild it in Icon Composer (free, in Apple's design resources) with
background and foreground layers, and add dark and mono variants. The current
render separates cleanly: gradient tile = background, note + sparkle =
foreground. Roughly an hour, no code changes.

### 2. Custom quality colours have no dark-mode variant — medium

**HIG (Color):** system colors "automatically adapt to vibrancy and
accessibility settings"; custom colors need to work in every appearance.

**App:** `ContentView.swift:1017-1019` defines three fixed colours
(`qualityGood`, `qualityWarning`, `qualityBad`) as deepened shades chosen to
sit on a 15 %-opacity tint in light mode. They are single values, so dark mode
gets the same dark green/amber/red on a dark background, where contrast is
likely to fall below 4.5:1.

**Fix:** move them into the asset catalogue as Color Sets with light and dark
appearances (lighter, more saturated in dark), or wrap them in a dynamic
`Color(nsColor: NSColor(name:dynamicProvider:))`. Small, but needs a visual
check in both appearances.

### 3. Keyboard shortcuts aren't in the menu bar — medium

**HIG (The menu bar):** "Mac users are very familiar with the macOS menu bar,
and they rely on it to help them learn what an app does and find the commands
they need. To help your app feel at home in macOS, it's essential to provide a
consistent menu bar experience."

**App:** ⌘O, ⌘R and ⌘I are attached to toolbar buttons
(`ContentView.swift`), so they work but appear nowhere in the menu bar.
`CleanMyDigitalApp.swift` declares no `.commands`, so the app ships with only
the default menus. Someone who doesn't hover every toolbar button can't
discover any shortcut.

**Fix:** add a `.commands` block — File: "Choose Folder… ⌘O", "Rescan ⌘R";
View: "Show Track Info ⌘I"; plus the auxiliary windows under a Window or Tools
menu. Small, and it makes the shortcuts self-documenting.

### 4. No privacy manifest — low here, blocker if you ever ship to the App Store

**App Store requirement:** apps using UserDefaults need `PrivacyInfo.xcprivacy`
declaring the reason code. Six files use `@AppStorage`/UserDefaults; the
project has no manifest.

**Effect:** none for a DMG you hand to testers. It becomes a submission
blocker the day you want the Mac App Store.

**Fix:** add `PrivacyInfo.xcprivacy` with `NSPrivacyAccessedAPICategoryUserDefaults`,
reason `CA92.1` (access to app's own defaults). Fifteen minutes.

### 5. One fixed font size — low

**HIG (Typography):** use text styles so text scales; macOS minimum is 10 pt.

**App:** `ContentView.swift:223` uses `.font(.system(size: 32))` for the glyph
in the category sheet. Everything else (126 uses) is a text style.

**Fix:** `.font(.largeTitle)` or `@ScaledMetric`. Minutes.

### 6. Accessibility hints are nearly absent — low

**HIG (Accessibility):** an accessible interface is perceivable and doesn't
rely on one channel; hints explain non-obvious actions.

**App:** 43 `accessibilityLabel`s but only one `accessibilityHint`. Controls
whose outcome isn't obvious from the label — "Correct…", "Re-match Album…",
"Collect Selected", the ⏹ in the progress pill — have no hint.

**Fix:** add hints to the dozen or so non-obvious controls. They already have
tooltips, so the wording exists.

## Already compliant

- **Type:** 126 text-style fonts, nothing below macOS's 10 pt minimum, no thin weights.
- **Accessibility:** 43 labels; the comparison rows merge both panes into one
  VoiceOver stop; "added" is never signalled by colour alone.
- **Motion:** one shared animation used everywhere, with a Reduce Motion branch.
- **Empty states:** 17 `ContentUnavailableView`s — every window explains itself when empty.
- **Materials:** no misuse on content; translucency only on headers and footers.
- **Feedback:** progress with counts and a Stop for long jobs, confirmation before
  folder renames, Undo for every file move, preview-before-apply everywhere.
- **Windows:** minimum and default sizes set per window; a proper Settings scene.
- **Search:** standard `.searchable` (so ⌘F works the way macOS expects).
- **Help:** all 19 toolbar controls have tooltips.

## Suggested order

1. Menu-bar commands (3) — small, most noticeable day to day.
2. Dark-mode colours (2) — small, fixes a real legibility issue.
3. Fixed font size (5) and hints (6) — minutes each.
4. Layered icon (1) — an hour, cosmetic but it's the app's first impression.
5. Privacy manifest (4) — only if the App Store is ever the plan.
